# «Классик»: Ubuntu 26.04 + Lomiri (UBports) на mainline-ядре для Samsung Galaxy M52 5G (m52xq)

Пробная сборка: настоящий Ubuntu-корень (arm64) + пакеты Ubuntu Touch (UBports) вместо postmarketOS/Alpine, на нашем mainline-ядре 7.1.2
(без Halium и Android). Этот файл — пошаговая инструкция с командами, чтобы любой мог повторить. Ведётся по мере работы, каждая
выполненная команда записывается сюда с результатом. Папка проекта: `убунтутач24/классик/`.

Статус на момент записи — см. раздел «Журнал» в конце.

## 0. Что получаем и зачем

- Базовая система: **Ubuntu 26.04 LTS «resolute» arm64** (корень собирается с нуля через `debootstrap`).
- Оболочка и приложения: **Lomiri 0.6.2** и остальное из репозитория UBports `26.04-1.x` (`http://repo.ubports.com`).
- Железо: тот же слой m52xq, что в нашей рабочей сборке (postmarketOS + Lomiri v4): ядро 7.1.2 + модули, прошивки, загрузочные образы
  `boot`/`vendor_boot`, службы и скрипты `m52xq-*`.
- Результат: образ `system` (GPT: p1 `pmOS_boot`, p2 `pmOS_root`), устанавливаемый тем же установщиком (`update-binary`) через TWRP.

Почему не Android/Halium: на mainline все драйверы родные Linux (DRM/KMS, ALSA, QMI-модем), поэтому libhybris и Android HAL не нужны —
Mir работает через `gbm-kms` и Mesa.

## 1. Что нужно на компьютере

Хост в нашем случае: Ubuntu 20.04 x86_64 (ядро 5.15), sudo без пароля для сборки, ≥ 20 ГБ свободного места, интернет.

```sh
# пакеты на хосте
sudo apt install debootstrap qemu-user-static binfmt-support gdisk rsync e2fsprogs curl openssl zip unzip util-linux
# проверить, что запуск arm64-бинарников через qemu включён
ls /proc/sys/fs/binfmt_misc/ | grep qemu-aarch64     # должен быть qemu-aarch64
cat /proc/sys/fs/binfmt_misc/qemu-aarch64 | head -3  # interpreter /usr/bin/qemu-aarch64-static, enabled
which debootstrap qemu-aarch64-static
debootstrap --version
```

Версии на нашем хосте: debootstrap 1.0.118ubuntu1.11 (знает релизы до jammy, про «resolute» не знает), `qemu-aarch64-static` версии 7.2 (`qemu-aarch64-static --version`).

Результат на 2026-10-27 (в списке много сборок, берётся самая новая — Candidate по `apt-cache policy lomiri` 0.6.2+0~20261024…): lomiri 0.6.2, lomiri-system-settings 1.3.2, mir-graphics-drivers-desktop 2.28.0, lomiri-keyboard 1.0.3,

## 3. Шаг 1: базовый корень Ubuntu 26.04 (debootstrap, ВАЖНО: свежая версия)

Хостовый debootstrap 1.0.118 (Ubuntu 20.04) НЕ годится для 26.04: он заранее создаёт ссылки `/bin`, `/lib`, `/sbin`, а `base-files` из 26.04
уже содержит их, и распаковка падает: `tar: ./bin: Cannot create symlink to 'usr/bin': File exists` /
`E: Tried to extract package, but file already exists`. Флаг `--merged-usr` и подсказка скрипта `gutsy` не помогают.
Решение: взять свежий debootstrap из архива Ubuntu и запустить его из временной папки (систему не менять):

```sh
cd убунтутач24/классик
mkdir -p tools/debootstrap-new && cd tools/debootstrap-new
curl -O http://archive.ubuntu.com/ubuntu/pool/main/d/debootstrap/debootstrap_1.0.144ubuntu1_all.deb
dpkg -x debootstrap_1.0.144ubuntu1_all.deb x
ls x/usr/share/debootstrap/scripts | grep resolute      # скрипт релиза resolute есть
DEBOOTSTRAP_DIR=$PWD/x/usr/share/debootstrap x/usr/sbin/debootstrap --version   # debootstrap 1.0.144ubuntu1
```

Скрипт `build-01-resolute.sh` (в папке `классик/`) делает первую и вторую стадию:

```sh
D=$PWD/tools/debootstrap-new/x
export DEBOOTSTRAP_DIR=$D/usr/share/debootstrap
sudo -E $D/usr/sbin/debootstrap --arch=arm64 --foreign --variant=minbase --no-check-gpg \
  --include=ca-certificates,gnupg,dbus,locales,python3,python3-gi,sudo,kmod,udev,iproute2,iputils-ping,openssh-server,network-manager,modemmanager,wpasupplicant,pipewire,pipewire-pulse,wireplumber,polkitd,alsa-utils,less,nano,systemd-sysv,libpam-systemd,tzdata \
  resolute rootfs-26.04-c http://ports.ubuntu.com/ubuntu-ports/
sudo cp /usr/bin/qemu-aarch64-static rootfs-26.04-c/usr/bin/
sudo chroot rootfs-26.04-c /debootstrap/debootstrap --second-stage
```

Грабли этого шага (все прошли по очереди, на каждой пришлось пересоздавать папку: КАЖДЫЙ запуск debootstrap — в НОВУЮ папку):
1. `E: Couldn't find these debs: pulseaudio` — в 26.04 нет `pulseaudio`: берём `pipewire`, `pipewire-pulse`, `wireplumber`; `policykit-1` → `polkitd`.
2. `file already exists` (из-за старого хостового debootstrap) — решено свежим debootstrap 1.0.144 (см. выше).
3. Вторая стадия остановилась: `dconf-service depends on default-dbus-session-bus | dbus-session-bus` — не хватает `dbus-user-session`.
   Починка внутри chroot: `apt-get -y install dbus-user-session` и `dpkg --configure -a` (см. шаг 2).
`--no-check-gpg`: ключи Ubuntu на хосте старые; для боевой сборки взять свежий `ubuntu-keyring` и убрать флаг.

## 4. Шаг 2: работа внутри корня (chroot под qemu)

Скрипт `chroot-run.sh` (в `классик/`) монтирует `/proc`, `/sys`, `/dev`, `/dev/pts`, копирует DNS и выполняет команду в корне:

```sh
./chroot-run.sh rootfs-26.04-c <команда...>
```

Дальше всё делается через него. Источники apt и доустановка:

```sh
# /etc/apt/sources.list внутри корня (debootstrap кладёт только «main»; добавляем остальное, updates и security)
cat > rootfs-26.04-c/etc/apt/sources.list <<'L'     # (под sudo; в нашей сборке файл писался через chroot-run.sh и rootfs-26.04-c.sources.sh)
deb http://ports.ubuntu.com/ubuntu-ports resolute main restricted universe multiverse
deb http://ports.ubuntu.com/ubuntu-ports resolute-updates main restricted universe multiverse
deb http://ports.ubuntu.com/ubuntu-ports resolute-security main restricted universe multiverse
L
./chroot-run.sh rootfs-26.04-c apt-get update
./chroot-run.sh rootfs-26.04-c apt-get -y install dbus-user-session
./chroot-run.sh rootfs-26.04-c dpkg --configure -a
```

Результат: рабочий корень Ubuntu 26.04 LTS (≈0,5 ГБ), `systemd` 259, `NetworkManager` 1.54, `ModemManager` 1.25, `pipewire` 1.6.

## 5. Шаг 3: Lomiri из репозитория UBports

Репозиторий UBports для 26.04 — набор `26.04-1.x`. Ключ репозитория на хосте/в корне не установлен, для пробной сборки
репозиторий подключён как доверенный (`Trusted: yes`); для боевой сборки поставить ключ UBports. Пакеты UBports приоритетнее Ubuntu (pin 1001):

```sh
# /etc/apt/sources.list.d/ubports.sources
Types: deb
URIs: http://repo.ubports.com/
Suites: 26.04-1.x
Components: main
Architectures: arm64
Trusted: yes
# /etc/apt/preferences.d/ubports.pref
Package: *
Pin: origin repo.ubports.com
Pin-Priority: 1001
```

```sh
./chroot-run.sh rootfs-26.04-c apt-get update
./chroot-run.sh rootfs-26.04-c apt-cache policy lomiri          # Candidate: lomiri 0.6.2+0~20261024… (та же версия, что у нас на Alpine)
./chroot-run.sh rootfs-26.04-c apt-get -y install ubuntu-touch-session     # 847 пакетов, весь Ubuntu Touch
```

Как запускается Lomiri в этой системе (важно для шага 6): пакет `ubuntu-touch-session` приносит пользовательские службы systemd
(`lomiri-full-greeter.service` запускает `/usr/libexec/lomiri-systemd-wrapper --mode=full-greeter`, то есть Lomiri сама служит композитором на Mir 2 через
DRM/KMS), цель `ubuntu-touch-session-unencrypted.target` и скрипт `/usr/bin/ubuntu-touch-session` (он выставляет окружение и вызывает
`/usr/share/ubuntu-touch-session/run-systemd-session`). Чтобы всё это стартовало, нужна обычная сессия пользователя (logind) — поэтому ниже
своя системная служба `m52xq-session.service` с автовходом на tty1 (как делал `tinydm` в postmarketOS) вместо lightdm.

## 6. Шаг 4: пустой образ GPT с теми же UUID и копия корня

Загрузочный initramfs (в `vendor_boot`) ищет корень по меткам/UUID образа v3, поэтому новый образ делаем с теми же значениями.
Образ — сектор 4096 байт (как у v3), p1 `pmOS_boot` ext2 (480 МиБ), p2 `pmOS_root` ext4 (5 ГиБ). Скрипт `build-03-image.sh rootfs-26.04-c`:

```sh
SECT=4096; P1_START=2048; P1_END=124927; P2_START=124928; P2_SECTORS=$((5*1024*1024*1024/SECT)); P2_END=$((P2_START+P2_SECTORS-1))
truncate -s $(( (P2_END + 1 + 40) * SECT )) samsung-m52xq-classic.img
L=$(sudo losetup -fP -b $SECT --show samsung-m52xq-classic.img)
sudo sgdisk -o $L
sudo sgdisk -n 1:$P1_START:$P1_END -t 1:EF00 -c 1:primary -u 1:C57D543F-2B8D-4F32-A27B-CDD7E68E1D76 \
            -n 2:$P2_START:$P2_END -t 2:8305 -c 2:primary -u 2:E7BC48A5-73CD-420C-916B-FC997CDB7486 $L
sudo losetup -d $L; L=$(sudo losetup -fP -b $SECT --show samsung-m52xq-classic.img)   # переподключить, чтобы появились p1/p2
sudo mkfs.ext2 -q -L pmOS_boot -U b58f3919-56c2-45b3-b952-281dcbace35a ${L}p1
sudo mkfs.ext4 -q -L pmOS_root -U 27c97050-ff55-4e42-b894-0f866eb5ad1f ${L}p2
mkdir -p mnt-new; sudo mount ${L}p2 mnt-new; sudo mkdir -p mnt-new/boot; sudo mount ${L}p1 mnt-new/boot
sudo rsync -aHAX --numeric-ids --exclude=/proc/* --exclude=/sys/* --exclude=/dev/* --exclude=/boot/* rootfs-26.04-c/ mnt-new/
sudo rm -f mnt-new/usr/bin/qemu-aarch64-static
```

Важно: образ v3 с 4096-байтовым сектором подключается только так: `losetup -fP -b 4096` (без `-b 4096` устройств `p1/p2` нет).

## 7. Шаг 5: слой железа m52xq из образа v3

Образ v3 берём из чанков архива (md5 образа `c5c772a77b675520da42ac87a61f5cc2`), подключаем только на чтение и копируем нужное. Скрипт `build-04-hardware.sh`:

```sh
cat ../003/archive-v3/data/rootfs-chunks/samsung-m52xq.img.part-0 ../003/archive-v3/data/rootfs-chunks/samsung-m52xq.img.part-1 > tools/v3.img
sudo losetup -fP -b 4096 --show tools/v3.img          # напр. /dev/loop18
mkdir -p mnt-v3; sudo mount -o ro /dev/loop18p2 mnt-v3
V=$PWD/mnt-v3; N=$PWD/mnt-new
sudo rsync -aH --chown=root:root $V/lib/modules/  $N/usr/lib/modules/        # модули ядра 7.1.2 (в Ubuntu /lib -> usr/lib)
sudo rsync -aH --chown=root:root $V/lib/firmware/ $N/usr/lib/firmware/       # прошивки (29 МБ)
sudo rsync -aH --chown=root:root $V/usr/local/    $N/usr/local/              # скрипты и данные m52xq-*
sudo rsync -aH --chown=root:root $V/etc/m52xq/    $N/etc/m52xq/
# udev-правила, юниты systemd, хуки сна, NM-конфиги, UCM звука, /usr/share/qcom и т. д. — полный список в build-04-hardware.sh
```

НЕ копируются бинарники под Alpine/musl (в Ubuntu не запустятся): их надо пересобрать или взять из пакетов Ubuntu
(Spacebar, звонилка Plasma Dialer, `libssc`, `pd-mapper`, наш `ath11k_ahb.ko` уже лежит в модулях, `libaa-unconfined.so`, `IntegratedLightDM` и т. п.).

## 8. Шаг 6: настройка внутри образа

Скрипт `chroot-config.sh` выполняется в chroot образа (`./chroot-run.sh mnt-new /bin/sh /tmp/cfg.sh`, до этого `sudo cp /usr/bin/qemu-aarch64-static mnt-new/usr/bin/`):

- имя узла `samsung-m52xq-classic`, `fstab` по меткам `pmOS_root`/`pmOS_boot`;
- локали `en_US.UTF-8`, `ru_RU.UTF-8`;
- пользователь `user` (uid 10000, пароль `1111`) и `root` с тем же паролем. ГРАБЛИ: `chpasswd` отказывается от пароля `1111`
  (`pam_chauthtok() failed`, проверка `pam_pwquality`), решение — готовый хеш: `HASH=$(openssl passwd -6 1111)`, затем `echo "user:$HASH" | chpasswd -e`;
- пакеты слоя Qualcomm из Ubuntu: `rmtfs tqftpserv qrtr-tools hexagonrpcd iio-sensor-proxy alsa-ucm-conf iw rfkill usbutils bluez`
  (`pd-mapper`, `libssc`, `tinydm` в Ubuntu 26.04 нет — нужно собрать самим);
- `depmod -a 7.1.2`;
- Ubuntu-вский `repowerd` и `lightdm` отключаем (`systemctl disable repowerd.service lightdm.service`): сессию стартует наша служба, питание изображает `m52xq-powerkey`;
- служба `m52xq-session.service` (аналог tinydm: автовход пользователя на tty1 через PAM, `ExecStart=/usr/bin/ubuntu-touch-session`, `Environment=GRID_UNIT_PX=21`), `systemctl set-default graphical.target`;
- включаем `m52xq-session`, `m52xq-usbnet` (USB-гаджет RNDIS + `172.16.42.1`), `m52xq-powerkey`, `ssh`, `NetworkManager`, `ModemManager`;
- `ssh-keygen -A` (ключи хоста), `: > /etc/machine-id`.

Перед упаковкой: `sudo rm -f mnt-new/usr/bin/qemu-aarch64-static`, `sudo umount mnt-new/boot mnt-new`, `sudo e2fsck -fn ${L}p2`, `sudo losetup -d $L`.

## 9. Шаг 7: упаковка в установочный zip (TWRP)

Установщик берём из архива v4 (`update-binary` + `updater-script`), правки: баннер, и ДОБАВЛЕН ТРЕТИЙ чанк (образ 5,9 ГБ не влезает в два):

```sh
mkdir -p archive-classic/data/rootfs-chunks archive-classic/mainline-extras/rootfs-files/etc/m52xq
cp -a ../003/archive-v4/META-INF ../003/archive-v4/firmware archive-classic/          # boot_v241_nfc + vendor_boot_v238_nfc_se9
sed -i 's|    samsung-m52xq.img.part-1 \\|    samsung-m52xq.img.part-1 \\\n    samsung-m52xq.img.part-2 \\|' archive-classic/META-INF/com/google/android/update-binary
split -b 2479603712 -d -a 1 samsung-m52xq-classic.img archive-classic/data/rootfs-chunks/samsung-m52xq.img.part-    # part-0, part-1, part-2
cat archive-classic/data/rootfs-chunks/samsung-m52xq.img.part-* | md5sum          # = md5 образа
cd archive-classic && zip -9 -r ../ubuntu-classic-26.04-m52xq-trial.zip . && cd ..    # ВАЖНО: внутри папки, без префикса
unzip -t ubuntu-classic-26.04-m52xq-trial.zip | tail -1
```

Результат первой сборки: образ 5 880 578 048 байт (md5 `2aa5172e07ce96e9970ac134c7fcf582`), zip 1 431 763 283 байт
(md5 `5e37c814edaf6150a04f442a1ab388c2`), `unzip -t` без ошибок. Установщик при установке берёт адрес Bluetooth, прошивку модема и реестр датчиков с самого телефона.

## 10. Установка и первая загрузка (НЕ выполнено, ждёт проверки)

Установка заменяет содержимое раздела `system` (то есть текущий Alpine-образ). Установленный ранее zip v4 лежит в `/data` и его можно поставить обратно.


Известные риски первой загрузки: initramfs ищет корень по меткам; `m52xq-powerkey` и другие скрипты написаны под Alpine
(busybox-утилиты, `/usr/libexec`), Lomiri 0.6.2 из UBports под Qt 6 на 26.04 может требовать настроек Mir под GPU Adreno
(`mir-graphics-drivers-desktop` 2.28), телефония (oFono/telepathy в UBports против ModemManager у нас) пока не настроена.

## 11. Быстрая проверка БЕЗ прошивки: образ как `/data/rootfs.img`

Загрузчик (ramdisk в `vendor_boot`) берёт `rootfs.img` из корня раздела `userdata` раньше, чем образ из `system`: порядок поиска —
SD-карта, USB-флешка, **`/data/rootfs.img`**, раздел `system`. Принимается GPT-образ pmbootstrap (p2 с меткой `pmOS_root`, сектор 4096), как у нас.
Поэтому проверить образ можно, не трогая `system` (прошивку).

```sh
# телефон загружен в текущую систему, USB-ssh работает: на работающей системе /data = /mnt/userdata
# заливка с компьютера (gzip -1 по ssh; sudo читает пароль первой строкой stdin), сначала под временным именем:
{ cat .pwu; echo; gzip -1 -c samsung-m52xq-classic.img; } | \
  sshpass -f .pwu ssh user@172.16.42.1 "sudo -S -p '' sh -c 'gunzip > /mnt/userdata/.rootfs.img.part'"
# сверить md5 на телефоне (должен совпасть с md5 образа 2aa5172e07ce96e9970ac134c7fcf582), потом переименовать:
ssh user@172.16.42.1 "sudo md5sum /mnt/userdata/.rootfs.img.part"
ssh user@172.16.42.1 "sudo mv /mnt/userdata/.rootfs.img.part /mnt/userdata/rootfs.img; sync"
# следующая перезагрузка стартует из этого образа
```

Скрипт: `push-to-data.sh` (в папке `классик/`, пароль берёт из файла `.pwu` в рабочей папке).
Время заливки 5,9 ГБ по USB-ssh: меньше минуты. Сверка md5 на телефоне прошла (`2aa5172e…`).

**Откат:** переименовать или удалить `/data/rootfs.img` (на работающей системе `sudo mv /mnt/userdata/rootfs.img /mnt/userdata/rootfs.img.off`, из TWRP:
`mv /data/rootfs.img /data/rootfs.img.off`): загрузка снова пойдёт из раздела `system` (postmarketOS v4).

## 12. Этап «в2»: от первой загрузки до рабочей оболочки Lomiri (2026-10-27)

После шага 11 телефон грузится из `/data/rootfs.img`, но Lomiri не поднимается. Здесь пошагово: как диагностировать, что чинить и какими командами.
Все правки собраны в папке `в2/`: `в2/rootfs-files/` (файлы с путями как в корне системы), `в2/debs*/` (пакеты), `в2/src/` (исходник заглушки), `в2/apply-fixes.sh`
(применяет всё к смонтированному образу), `в2/ПРАВКИ.md` (хронология 47 находок).

### 12.1. Как читать журнал образа из TWRP (только чтение, ничего не ломает)

Телефон в TWRP, образ лежит в `/data/rootfs.img`. Раздел p2 (корень) — GPT с сектором 4096: смещение = 124928 × 4096 = 511705088 байт
(проверка на компьютере: `sudo losetup -r -f --show -b 4096 -P samsung-m52xq-classic.img; sudo sgdisk -p /dev/loopN`).


### 12.3. Lomiri не стартует: графика и «заглушка Halium»

1. **Нет платформ графики Mir 1** (`/usr/lib/aarch64-linux-gnu/mir1/server-platform`): Lomiri 0.6.2 из UBports собран под Mir **1.8**, а не Mir 2.


   Сборка (в chroot Ubuntu, gcc ставится `apt-get install gcc libc6-dev`): `gcc -shared -fPIC -O2 -o libm52xq-noprops.so noprops.c`.

3. **Ловушка: пакет `libhybris`** (тянется веб-движком Qt WebEngine для браузера) кладёт `/usr/share/glvnd/egl_vendor.d/10_libhybris.json`; он перебивает Mesa → Mir пишет

4. **`/tmp/.X11-unix`**: `Mir fatal error: Failed to bind socket /tmp/.X11-unix/X3` — `/etc/tmpfiles.d/m52xq-x11.conf`:

5. **`deviceinfo`**: без файла устройства Lomiri считает телефон настольным ПК с альбомной ориентацией. `/etc/deviceinfo/devices/m52xq.yaml`

6. Режим: Mir выбирает `mir:mesa-kms` (графика, msm DRM) и `mir:evdev-input` (мультитач). `EGL_WL_bind_wayland_display` в логах — только предупреждение.

### 12.7. Заставка загрузки (Plymouth)

Тема `m52xq-ubuntu-touch` (розовый фон, логотип, 5 точек; `в2` берёт её из образа). Что нужно, чтобы она заработала:

1. **«splash» в cmdline нет** → `plymouthd` создаёт только текстовые устройства (чёрный экран). `/etc/systemd/system/plymouth-start.service.d/m52xq.conf`:
   ```ini
   [Unit]
   ConditionKernelCommandLine=
   [Service]
   ExecStart=
   ExecStart=/usr/sbin/plymouthd --mode=boot --pid-file=/run/plymouth/pid --attach-to-session --kernel-command-line="quiet splash"
   ```
   и `/etc/plymouth/plymouthd.conf` с `Theme=m52xq-ubuntu-touch`. Диагностика: `plymouthd --no-daemon --debug --debug-file=/tmp/ply.txt --kernel-command-line="quiet splash"`.
2. **SEGV в script-плагине** — нет модулей текста: `apt-get download plymouth-label` и `dpkg -i` (в `в2/debs-plymouth/`).
3. **Чёрная пауза после заставки (~13 с)**: штатный `plymouth-quit` гасил её через 2 с, а Lomiri стартовал позже. Решение (без блокировки загрузки):
   * замаскировать `plymouth-quit.service` и `plymouth-quit-wait.service` (`systemctl mask`), чтобы ничто не ждало Plymouth;
   * `/etc/sudoers.d/m52xq-plymouth` (`root:root`, 0440): `user ALL=(root) NOPASSWD: /usr/bin/plymouth quit --retain-splash`;
   * `/etc/systemd/user/lomiri-full-greeter.service.d/m52xq-plymouth.conf`: `ExecStartPre=-/usr/bin/sudo -n /usr/bin/plymouth quit --retain-splash`
     (заставка гасится прямо перед Mir, картинка остаётся до первого кадра);
   * запасная служба `m52xq-plymouth-fallback.service` (`sleep 40; plymouth quit --retain-splash`, не блокирует загрузку).
   **НЕЛЬЗЯ:** привязывать гашение к ожиданию greeter, оставляя `plymouth-quit-wait` — взаимная блокировка (`multi-user.target` ждёт Plymouth, Plymouth ждёт greeter, greeter ждёт `graphical.target`) —
   телефон «висит на заставке»; снимается `plymouth quit` под root по ssh.
4. **Яркость заставки почти 0:** `systemd-backlight@backlight:ae94000.dsi.0` восстанавливал сохранённую яркость 0 (`Saved brightness 0 is too low; increasing to 12`).
   `systemctl mask systemd-backlight@backlight:ae94000.dsi.0.service`, сохранённое убрать из `/var/lib/systemd/backlight/`; яркостью занимается `m52xq-powerkey` (по умолчанию 180).
5. Тише консоль: `/etc/sysctl.d/90-m52xq-quiet.conf`: `kernel.printk = 0 0 0 0`.
   Результат (подтверждён пользователем): заставка до запуска Lomiri, чёрными остаются ~5 с на первый кадр.

### 12.8. Экранная клавиатура (maliit) — подробно

Без клавиатуры нельзя ввести пароль Wi-Fi (мастер, Настройки). Заработала после шести независимых правок; каждая нужна, и по одной не помогает. Решение «как в pmOS» было взято частично.

**Схема:** Lomiri (клиент) загружает Qt-плагин `maliit-inputcontext-qt5` (`QT_IM_MODULE=maliit`) → по D-Bus (`org.maliit.server`) говорит с `maliit-server` → тот рисует клавиатуру отдельным Wayland-окном (QML `lomiri-keyboard`).

1. **Lomiri считал кнопки клавиатурой.** Питание/громкость (`pmic_pwrkey`, `pmic_resin`, `gpio-keys`) — устройства с клавишами, поэтому `oskEnabled=false`. Правка `usr/share/lomiri/OrientedShell.qml`
   (из pmOS, оригинал md5 `72e6942f…` совпал с классиком, правленый `215dbad2…`): такие устройства не считаются; плюс таймер раз в 2 с вызывает `requestActivate()` окна оболочки (без этого maliit не получает `setFocusObject`).
   ```bash
   cp в2/rootfs-files/usr/share/lomiri/OrientedShell.qml /usr/share/lomiri/OrientedShell.qml     # на телефоне, root
   ```
2. **`QT_IM_MODULE` не был задан** — `/etc/environment.d/92-m52xq-im.conf`: `QT_IM_MODULE=maliit`
   (проверка: `tr '\0' '\n' < /proc/$(pgrep -u user -x lomiri|head -1)/environ | grep IM_MODULE`; в логе Lomiri при касании поля появляется `org.maliit.inputContext: showInputPanel()` — для этого
   `systemctl --user set-environment "QT_LOGGING_RULES=org.maliit*=true"` и перезапуск `lomiri-full-greeter`).
3. **`maliit-server` падал по кругу** (Qt перебирал `ubuntumirclient;wayland-egl;xcb`). Нужен drop-in `/etc/systemd/user/maliit-server.service.d/m52xq.conf`:
   ```ini
   [Service]
   Environment=MALIIT_FORCE_DBUS_CONNECTION=1   # на платформе wayland maliit иначе берёт Wayland-соединение и НЕ регистрируется как org.maliit.server
   Environment=QT_QPA_PLATFORM=wayland-egl
   Environment=EGL_PLATFORM=wayland
   UnsetEnvironment=DISPLAY QT_IM_MODULE         # DISPLAY=:0 → Mesa берёт EGL платформы x11 (сервера нет) → ЗАВИСАНИЕ; QT_IM_MODULE у сервера → подключается сам к себе
   ExecStart=
   ExecStart=/usr/bin/maliit-server
   ```
   Что НЕ работает: `-platform wayland` в командной строке (maliit печатает usage, но платформу берёт); `QT_QUICK_BACKEND=software` — сервер падает SEGV в `UCLomiriShape::createSceneGraphNode`
   (виджеты Lomiri Toolkit требуют контекст OpenGL; backtrace через gdb: `gdb -batch -ex run -ex bt --args /usr/bin/maliit-server` в окружении службы).
4. **Раскладки** — пакеты `lomiri-keyboard-russian/arabic/korean/japanese/chinese-pinyin/emoji` (+ словари hunspell-ru/ar/ko, anthy, libpinyin): скачать с зависимостями
   (`apt-get install -s … | grep ^Inst`, `apt-get download …` в chroot), поставить `dpkg -i` (в `в2/debs-keyboard/`). Пакета хинди нет. Языки (от имени user):
   ```bash
   export DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/10000/bus
   gsettings set com.lomiri.keyboard.maliit enabled-languages "['en','ru','emoji']"; gsettings set com.lomiri.keyboard.maliit active-language "ru"
   ```
5. После правок: `systemctl --user restart maliit-server; systemctl --user restart lomiri-full-greeter` (клиент подключается к D-Bus-серверу при старте — сначала сервер, потом Lomiri, иначе клавиатура не появится).
6. Проверка: `busctl --user list --no-legend | awk '{print $1}' | grep maliit` → `org.maliit.server`; в журнале сервера `keyboard is reporting <x y w h>: < 0 1539 1080 861 >` = клавиатура показана.

### 12.9. Дополнения к ловушкам (этап клавиатуры и мастера)

* **GL у клиентов Lomiri:** `libEGL warning: failed to get driver name for fd -1` — безвредное предупреждение (EGL-клиенты на Mir 1.8 + Mesa 26 всё равно рисуют: калькулятор выдаёт кадры). Но если задан `DISPLAY`,
  Mesa выбирает платформу x11 — для клиентов, запущенных не Lomiri'ем, `unset DISPLAY` или `EGL_PLATFORM=wayland`.
* **Флаг мастера** `~/.config/lomiri/wizard-has-run` создаётся ЗАНОВО после прохождения мастера. Чтобы увидеть мастер ещё раз: `mv ~/.config/lomiri/wizard-has-run{,.removed}` и перезапуск greeter
  (`systemctl --user restart lomiri-full-greeter`). В образ флаг попадать не должен (`apply-fixes.sh` его удаляет).
* **Копирование на телефон:** не `tar|cp -a` (владельцы каталогов), а `ssh root@… install -m644 -o root -g root`, `scp` + `install`, либо `printf … > файл; chown root:root`. Root по ssh работает (пароль m52xq), даже когда `sudo` сломан.
* **gdb на телефоне:** `в2/debs-gdb/` (gdb, libpython3.14 — `dpkg -i` ругается на зависимость libpython3.14-stdlib, но gdb работает); перезаливка образа с компьютера стирает его — ставить заново.

### 12.11. Ловушки этапа (коротко)

* `tar | cp -a` на телефон переносит ВЛАДЕЛЬЦА каталогов (`/etc`, `/etc/sudoers.d` стали uid 10000) → `sudo: /etc/sudoers.d is owned by uid 10000`. Копировать файлы через `install -m… -o root -g root`
  или под root по ssh; в `apply-fixes.sh` — `cp -a --no-preserve=ownership` и `chown -R root:root`.
* Часы телефона отстают (апрель 2026): `tar: time stamp … is in the future` — безвредно.
* `systemctl stop m52xq-session` держится до 90 с (SIGKILL по таймауту); после неудачной остановки `OnFailure=getty@tty1` занимает экран: `systemctl reset-failed m52xq-session; systemctl stop getty@tty1; systemctl start m52xq-session`.
* Никогда не читать `/sys/kernel/debug/*` на этом телефоне (заметки проекта: сбросы SoC).
* Живые правки сохраняются только в том образе, который сейчас смонтирован как корень (`/data/rootfs.img`); перезаливка образа с компьютера их стирает — поэтому всё занесено в `в2/rootfs-files` и `apply-fixes.sh`.

### 12.15. Блокировка экрана и пароль

* Короткое нажатие питания не блокировало: `DBusLomiriSessionService::CanLock()` (Lomiri 0.6.2, `plugins/Lomiri/Session/dbuslomirisessionservice.cpp`) возвращает `false` пользователям из группы **`nopasswdlogin`**,
  а автовход greeter держался на этой группе (`/etc/pam.d/lightdm`: `auth sufficient pam_succeed_if.so user ingroup nopasswdlogin`). Группа должна остаться без членов (`gpasswd -d user nopasswdlogin`).
* Пароль пользователя: `printf 'user:%s\nroot:%s\n' "$(openssl passwd -6 1111)" ... | chpasswd -e` (обычный `chpasswd` падает: `pam_chauthtok() failed` — `pam_extrausers` не знает `YESCRYPT`); `cat /etc/shadow > /etc/shadow.m52xq.bak`.
  Мастер Lomiri сам ставит пользователю пустой пароль (`user::` в shadow).
* Форма ввода на экране блокировки: `busctl --system set-property org.freedesktop.Accounts /org/freedesktop/Accounts/User10000 com.lomiri.AccountsService.SecurityPrivacy PasswordDisplayHint i 1`
  (0 — клавиатура, 1 — цифровая панель с анимацией кружков). Хранится в `/var/lib/AccountsService/users/user`.
* Скрипт кнопки питания `m52xq-powerkey` теперь пишет в журнал `short power key`, `setScreenPowerMode …` (диагностика «экран сам включается»).


### 12.16. Звук (PipeWire) и сохранение пароля

**Звук — рабочая схема (подтверждено: слышны звонок и голос, после перезагрузки звук есть):**
1. Звуковая карта появляется только после запуска ADSP: включить `m52xq-adsp-start.service` и `m52xq-audio-reprobe.service` (в классике лежали `disabled`):
   ```bash
   systemctl enable --now m52xq-adsp-start.service m52xq-audio-reprobe.service
   cat /proc/asound/cards        # 0 [SMM526BWCD938X ]: sm8250 - SM-M526B-WCD938X
   ```
2. UCM-профиль `Qualcomm/sm7325/SM-M526B/HiFi.conf` — тот же, что в pmOS (md5 `8ad33c0e…`): динамик = `QUIN_MI2S_RX Audio Mixer MultiMedia1`=1 (усилитель TFA9878 на QUINARY MI2S).
   Проверка железа в обход звукового сервера: `aplay -D hw:0,0 -f S16_LE -r 48000 -c 2 /usr/share/sounds/alsa/Front_Center.wav` (S24/S32 драйвер не принимает).
3. **PulseAudio из набора Ubuntu Touch не годится:** sink динамика создаётся в состоянии `SUSPENDED` с причиной `APPLICATION` и не просыпается ни `pactl suspend-sink 0`, ни D-Bus `Device.Suspend(false)`, ни перезапуском демона.
   Перешли на **PipeWire**: в пользовательском менеджере `pulseaudio.service` и `pulseaudio.socket` замаскированы (`ln -s /dev/null /etc/systemd/user/pulseaudio.{service,socket}`),
   работают `pipewire`, `wireplumber` и `pipewire-pulse` (`pactl info` → `PulseAudio (on PipeWire 1.6.2)`). Индикатор звука (`ayatana-indicator-sound`) подключается к нему сам.
4. WirePlumber открывал ALSA в `S24_LE` — **тишина при состоянии RUNNING**. `/etc/wireplumber/wireplumber.conf.d/51-m52xq-alsa.conf`:
   `monitor.alsa.rules` с `update-props { audio.format = "S16LE", audio.rate = 48000, audio.allowed-rates = [48000] }` для `alsa_output.*` и `alsa_input.*`. Проверка: `cat /proc/asound/card0/pcm0p/sub0/hw_params` во время воспроизведения → `format: S16_LE`.
5. Громкость по умолчанию: `wpctl set-volume @DEFAULT_AUDIO_SINK@ 0.7; wpctl set-mute @DEFAULT_AUDIO_SINK@ 0`. Диагностика PA-демона: `pacmd set-log-level 4` и `pacmd list-sinks` (`suspend cause`).

**Пароль откатывался после каждой загрузки** (`1111` → `m52xq`): ramdisk до systemd перезаписывает `/etc/shadow` (и `/etc/fstab`) старой копией, прежний файл кладёт как `*.m52xq.bak`
(у обоих mtime 1970 — запись до установки часов). Обход, как в pmOS: `m52xq-password-backup.path` (`PathModified=/etc/shadow` → `cp -a /etc/shadow /etc/.m52xq-shadow-backup`)
и `m52xq-password-restore.service` (`WantedBy=sysinit.target`, `Before=sysinit.target`, `ConditionPathExists=/etc/.m52xq-shadow-backup`, `cp -a` обратно). Включить: `systemctl enable m52xq-password-restore.service m52xq-password-backup.path`;
пароль задавать `printf 'user:%s\nroot:%s\n' "$(openssl passwd -6 1111)" "$(openssl passwd -6 1111)" | chpasswd -e` (обычный `chpasswd` падает на `YESCRYPT`), затем `cp -a /etc/shadow /etc/.m52xq-shadow-backup`.
Не включать `m52xq-set-default-password.service` (ставит 112233 при первой загрузке).


### 12.17. Автоповорот и датчики (SSC через libssc)

Акселерометр, датчик света и приближения этого телефона находятся **на ADSP** (Qualcomm Sensor Core) и доступны только через `libssc`. В Ubuntu нет `libssc`, а `iio-sensor-proxy` 3.8 собран без SSC-драйверов. Решение — как в pmOS: собрать `libssc` и `iio-sensor-proxy` 3.9 под glibc.

1. **Сборка** (чистый chroot Ubuntu 26.04 arm64 — без репозитория UBports, иначе apt понижает пакеты; каталог `в2/build-sensors/`):
   ```bash
   # зависимости: libqmi-glib-dev libqrtr-glib-dev libgudev-1.0-dev libprotobuf-c-dev protobuf-c-compiler protobuf-compiler libprotobuf-dev python3-protobuf python3-gi python3-dev gobject-introspection libgirepository1.0-dev libpolkit-gobject-1-dev
   curl -L https://codeberg.org/DylanVanAssche/libssc/archive/v0.4.4.tar.gz -o libssc-0.4.4.tar.gz       # sha512 9240970f…
   tar xzf libssc-0.4.4.tar.gz && cd libssc && patch -p1 < libssc-m52xq-0003-proximity-report-dump.patch   # патч проекта (датчик приближения Samsung)
   meson setup output --prefix=/usr --libdir=lib/aarch64-linux-gnu --buildtype=release -Db_lto=false && meson compile -C output && DESTDIR=/build/ssc-dest meson install -C output
   cp -a /build/ssc-dest/usr/. /usr/ && ldconfig                                                               # чтобы iio-sensor-proxy нашёл libssc
   curl -L https://gitlab.freedesktop.org/hadess/iio-sensor-proxy/-/archive/3.9/iio-sensor-proxy-3.9.tar.gz | tar xz
   meson setup output --prefix=/usr --libexecdir=lib -Dssc-support=enabled && meson compile -C output       # бинарь: output/src/iio-sensor-proxy
   ```
2. **Файлы на телефоне** (все лежат в `в2/rootfs-files`, владелец root): `/usr/lib/aarch64-linux-gnu/libssc.so.2`, `/usr/bin/ssccli`, `/usr/local/libexec/iio-sensor-proxy` (пакетный `/usr/libexec/iio-sensor-proxy` 3.8 не трогаем),
   пакет `libprotobuf-c1` (`в2/debs-sensors/`), `/etc/udev/rules.d/99-m52xq-libssc.rules` (`ENV{IIO_SENSOR_PROXY_TYPE}="ssc-accel ssc-light ssc-proximity"`, `ACCEL_MOUNT_MATRIX="-1, 0, 0; 0, -1, 0; 0, 0, 1"` — поворот на 180°,
   акселерометр lsm6dsm стоит «вверх ногами»), `/etc/xdg/QtProject/Sensors.conf` (`[Default] QOrientationSensor = iio-sensor-proxy.orientationsensor` — qtmir берёт ориентацию у proxy).
3. **Службы** (`/etc/systemd/system`): `hexagonrpcd-adsp-sensorspd.service` (`/usr/bin/hexagonrpcd -f /dev/fastrpc-adsp -d adsp -s -R /usr/share/qcom/sm7325/Samsung/m52xq`) и `hexagonrpcd-adsp-rootpd.service` (то же без `-s`),
   оба `User=fastrpc`, `After=m52xq-adsp-start.service`, `ExecStartPre` ждёт появления `/dev/fastrpc-adsp` до 120 с; **штатный `hexagonrpcd.service` Debian замаскировать** (`systemctl mask hexagonrpcd.service`): его обёртка берёт каталог
   `/var/lib/droid-juicer/sensors/` (нет) → «Could not read from directory». `iio-sensor-proxy.service.d/m52xq.conf`: `ExecStart=/usr/local/libexec/iio-sensor-proxy`, `RestrictAddressFamilies=… AF_QIPCRTR` (libssc говорит с ADSP по QRTR),
   `After=hexagonrpcd-adsp-sensorspd.service`, `ExecStartPre` ждёт до 60 с потока `ssccli --sensor accelerometer` (proxy опрашивает датчики один раз при старте).
4. **ГЛАВНОЕ — реестр датчиков:** без каталога `/usr/share/qcom/sm7325/Samsung/m52xq/sensors/registry/` (139 файлов: `lsm6dsm_0.*`, `stk3a9x_0.*`, `ak0991x_0.*`, `sns_*` — заводская калибровка из раздела **persist** этого телефона)
   служба SSC в ADSP поднимается, но датчики не регистрируются, `ssccli` молчит, в журнале `hexagonrpcd`: «Could not open /mnt/vendor/persist/sensors/registry/registry». Копия лежит в `в2/rootfs-files/…/registry` (владелец `fastrpc`, файлы 600, каталог 755; **не публиковать** — калибровка конкретного аппарата).
   Как получить заново: смонтировать раздел `persist` (`/dev/block/sda5`, в TWRP) и скопировать `persist/sensors/registry/registry/*`.

### 12.18. Фонарик в шторке

Переключатель «Фонарик» — часть `ayatana-indicator-power` (UBports-версия, сервис работает **от пользователя**). Бэкенд по умолчанию: запись в `/sys/class/leds/white:flash/brightness`
(путь вшит в бинарник; других настроек `deviceinfo` не требуется). На классике файл принадлежал `root:root` с правами `644`, поэтому запись давала `Permission denied` и фонарик не включался.
Правило `/etc/udev/rules.d/90-m52xq-flashlight.rules`:
```
SUBSYSTEM=="leds", KERNEL=="white:flash", RUN+="/bin/chgrp video /sys%p/brightness", RUN+="/bin/chmod 664 /sys%p/brightness"
```
Применить без перезагрузки: `udevadm control --reload; udevadm trigger --action=add --subsystem-match=leds --sysname-match="white:flash"`. Проверка: `ls -l /sys/class/leds/white:flash/brightness` → `root video 664`;
`su -s /bin/sh user -c 'test -w /sys/class/leds/white:flash/brightness && echo ok'`. Пользователь `user` уже в группе `video`. Светодиод: максимум яркости 8, драйвер на i2c-шине `24-0049`.


### 12.19. Шторка: переходы в настройки, Bluetooth, беззвучный режим

* **Индикаторы определяют Lomiri по `XDG_CURRENT_DESKTOP`.** Без неё `ayatana-indicator-power|sound|display|bluetooth|session` (функция `ayatana_common_utils_is_lomiri`) открывали настройки через `unity-control-center`
  (GTK-программа; в журнале `Unrecognized value "gl-gles"` про `GDK_DEBUG`) вместо `settings:///system/…` и вели себя как на десктопе. `lomiri-indicator-network` (Wi-Fi) вызывает URL-диспетчер всегда — поэтому только он работал.

### `chroot-run.sh` — Шаг 2: запуск команды в chroot

```sh
#!/bin/sh
# классик: выполнить команду внутри корня Ubuntu (chroot под qemu) с /proc, /sys, /dev, DNS и обычным PATH.
# Использование: ./chroot-run.sh <папка корня> <команда...>   (например ./chroot-run.sh rootfs-26.04-c apt-get update)
R=$(cd "$(dirname "$0")" && pwd)/$1; shift
sudo mount --bind /proc "$R/proc"; sudo mount --bind /sys "$R/sys"; sudo mount --bind /dev "$R/dev"; sudo mount --bind /dev/pts "$R/dev/pts"
sudo cp /etc/resolv.conf "$R/etc/resolv.conf" 2>/dev/null
sudo chroot "$R" /usr/bin/env -i HOME=/root TERM=xterm PATH=/usr/sbin:/usr/bin:/sbin:/bin DEBIAN_FRONTEND=noninteractive "$@"
rc=$?
sudo umount "$R/dev/pts" "$R/dev" "$R/sys" "$R/proc" 2>/dev/null
exit $rc
```

### 12.20. Звук пропадает при блокировке экрана (Lomiri останавливает приложения)

Симптом: музыка/видео (в том числе на Bluetooth-наушниках) замолкает при блокировке и возвращается при разблокировке.

Диагностика (по ssh `root@172.16.42.1`, пароль 1111):

```
# поток на наушники не прекращается — счётчики ACL растут и при погашенном экране
hciconfig hci0 | grep -E "ACL|TX|RX"
# а процессы приложения остановлены:
for p in $(pgrep -f "morph-browser$|QtWebEngineProcess"); do awk '/^State/{print $2,$3}' /proc/$p/status; done   # T (stopped)
```

Причина: `Stage.qml` выставляет `exemptFromLifecycle = !isTouchApp || isExemptFromLifecycle(appId) || temporaryAwaken`; приложения вне списка при уходе с переднего плана получают SIGSTOP. Список — GSettings `com.canonical.qtmir lifecycle-exempt-appids` (по умолчанию `['music.ubports']`).

Живая проверка:

```
su -s /bin/sh user -c "XDG_RUNTIME_DIR=/run/user/10000 DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/10000/bus gsettings set com.canonical.qtmir lifecycle-exempt-appids \"['music.ubports', 'morph-browser']\""
```

Затем закрыть приложение и открыть заново (остановленный процесс правило не подхватывает), включить звук, заблокировать — звук идёт (подтверждено).

В образе: секция `[com.canonical.qtmir]` в `rootfs-files/usr/share/glib-2.0/schemas/99-m52xq-lomiri.gschema.override`, схемы компилирует `glib-compile-schemas` в `apply-fixes.sh`. Цена — приложение из списка не засыпает в фоне (заряд); другие «звуковые» приложения добавлять в тот же список по короткому appId.

Попутный замер (п. 99 ПРАВКИ): 4K в морфе декодируется программно (≈218 % CPU у QtWebEngineProcess), GPU (kgsl, 315 МГц) только композитит; аппаратное декодирование Venus — следующий этап.

### 13.1. Принципы (выучено за день)

### 13.2. Приложения из OpenStore (click)
Установка пакета: `OpenStore 4.2.0-20.04` (focal, arm64) — `click install --user=user --allow-unauthenticated файл.click` (от root: `click install --user=user …`; от пользователя нужен владелец `/opt/click.ubuntu.com`). Что пришлось добавить (по причинам вылета/«не ставится»):
1. `/usr/share/click/frameworks/*.framework` — 16 файлов (`ubuntu-sdk-15.04…20.04.1`, `ubuntu-touch-24.04-1.x`): магазин фильтрует каталог по установленным framework.
2. `/usr/local/bin/pkcon` — OpenStore ставит командой `pkcon install-local --allow-untrusted файл` и удаляет `pkcon remove имя;версия;all;local:click`; в Ubuntu нет ни pkcon, ни click-бэкенда PackageKit. Заглушка зовёт `click install/unregister` от текущего пользователя.
3. `/etc/tmpfiles.d/click.conf` (`d /opt/click.ubuntu.com 0755 user user`) — штатный `/usr/lib/tmpfiles.d/click.conf` при каждой загрузке отдавал каталог `clickpkg`.
4. `dpkg-divert /usr/bin/aa-exec` и `/usr/bin/aa-clickhook` → заглушки (`/usr/local/lib/m52xq-click/`): AppArmor в ядре нет («profile … does not exist», «Hook command aa-clickhook failed»). Заглушка `aa-exec` отбрасывает профиль, ставит `QT_QPA_PLATFORM=wayland-egl` (список `ubuntumirclient;…` ронял Morph Qt6 через libhybris) и `LD_LIBRARY_PATH` с `libxml2.so.2`-совместимостью, запускает через `m52xq-app-env`.
5. `ln -s user /opt/click.ubuntu.com/.click/users/phablet` — OpenStore спрашивает libclick про пользователя «phablet» (иначе всё «Установить» после установки).
6. `m52xq-click-desktops.path/.service` — копирует `~/.local/share/applications/*.desktop` с `X-Lomiri-Application-ID` в `/custom/xdg/data/applications` (Lomiri читает только `/custom/xdg/data:/usr/share:/custom/usr/share`), пишет только изменившееся.
7. `GLIBC_TUNABLES=glibc.rtld.optional_static_tls=65536` в `m52xq-app-env` — YouTube (QtWebEngine UBports → libhybris) падал «cannot allocate memory in static TLS block».
8. `LD_LIBRARY_PATH=…/m52xq-mesa` в `m52xq-app-env` — Lomiri не передаёт его click-приложениям, без этого видео на программной графике.

Проверка: `click list --user=user`; запуск как Lomiri: `systemd-run --user -M user@ --wait --pipe -p WorkingDirectory=/opt/click.ubuntu.com/.click/users/user/ПАКЕТ -E WAYLAND_DISPLAY=wayland-0 aa-exec-click -p ИД_ПРИЛОЖЕНИЯ -- КОМАНДА`.
Что НЕ вышло: **Morph Browser Qt6** (пакет 24.04, 151 МБ) — нужны ICU 74, libxml2 2.9.14, Boost 1.83, exiv2 (из архива noble, кладутся внутрь папки пакета), видео на CPU (≈540 %), цвета перепутаны R↔B, вешал телефон — удалён. Видео в браузерах (Qt 5 WebEngine) остаётся на CPU.

- Запуск вручную из ssh: `su -s /bin/sh user -c "XDG_RUNTIME_DIR=/run/user/10000 DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/10000/bus XDG_DATA_DIRS=/custom/xdg/data:/usr/share setsid nohup gtk-launch lomiri-camera-app >/dev/null 2>&1 &"` (так вывод приложения в журнал не попадает).
- Если камера «занята» (`Failed to setup link … Device or resource busy`): закрыть приложение **по PID** (`pgrep -x lomiri-camera-a`; `kill`, при необходимости `kill -9`), затем `media-ctl -d /dev/media0 -r`.
- **Грабли:** (а) **`m52xq-virtualcam` нельзя включать на автозапуск** — после `systemctl enable` оба модема при загрузке были `failed: sim-missing` (141), после `disable --now` + `rmmod v4l2loopback` — норма; родной камере он не нужен; (б) в `/usr/share/lomiri-camera-app/qml` файлы правятся на телефоне напрямую, пакет в hold, оригиналы — в `/root/camera-orig/`.
- **«16 Мп» = 4608×3456, а не 4624×3468** (патч `m52xq-16mp-binned.patch`): из кадра 4624×3468 soft-ISP выдаёт максимум 4616 px по ширине, поэтому для 4624 libcamera уходила на полный кадр 9248×6936 с яркой шахматкой 8×6 плиток (особенно в темноте); 4608×3456 читается напрямую из бинированного режима датчика — чисто и с меньшим шумом (так делал и Megapixels в pmOS). 64 Мп остаётся полным кадром — шахматка там есть. Проверка без приложения: `gst-launch-1.0 -e libcamerasrc camera-name=/base/soc/cci@ac4a000/i2c-bus@0/camera@2d ! video/x-raw,format=BGRx,width=4608,height=3456 ! … jpegenc ! multifilesink`.
- Известные недостатки: шахматка при 64 Мп, шум после постобработки заметен при 100 %, зум щипком отключён.

- **Видео 4K (задняя и фронтальная)** (п. 149–150): в запасной список видеоразмеров добавлен 3840×2160 (`m52xq-video-4k.patch`), для видео ≥4K видоискатель тоже 4K (иначе «not negotiated», запись зависает на 00:00) — правка в `ViewFinderOverlay.qml` (в `m52xq-tap-focus.patch`). Запись идёт через Venus (`m52xqvenc`): задняя 4K ≈ 23 к/с по видеодорожке (узкое место — `videoconvert` BGRx→NV12 на CPU и 4K-превью), 1080p ≈ 57 к/с, ≈ 43 Мбит/с в 4K, звук AAC записывается. Для 30 к/с в 4K нужен путь «сырой поток + GPU + dma-buf» как у plasma-camera r58 из pmOS.
- **Известные проблемы видео (2026-10-29, не решены):** (1) звук в роликах очень тихий (пик −8…−17 дБFS, средний ≈ −50 дБFS; усиление микрофона: ADC1 16/20 = 24 дБ, TX_DEC0 94 = +10 дБ; динамик по умолчанию 29 % = −31,9 дБ) — нужен замер при речи и, возможно, программное усиление записи или повышение ADC; (2) 4K-ролик с фронтальной не воспроизводится родным `lomiri-mediaplayer-app` (Qt 5; файл целый, Venus-декодер проигрывает его ≈ 60 к/с, плеер на 4K грузит CPU и молчит) — проверить 4K задней в том же плеере; (3) при записи 4K свободной памяти остаётся ≈ 140 МБ из 4,9 ГБ, подкачки нет (`zram0` есть, но не включён) — риск OOM на долгой записи; съёмка 31 Мп с фронтальной убивает камеру (OOM).

## 15. Сборка архива в2 (2026-10-29)

Архив в2 — установочный zip для TWRP (структура как в разделе 9). **Корень собран не прогоном `apply-fixes.sh` на чистом образе, а снимком живой системы телефона**: на телефоне за 2 дня накопилось 2273 изменённых файла (в т. ч. то, что не попало в `rootfs-files`), и снимок воспроизводит проверенное состояние.

```sh
  -E lazy_itable_init=0,lazy_journal_init=0 ${L}p2          # те же параметры, что у базового p2 (опций ^orphan_file/^uninit_bg у этого mke2fs нет)
```
