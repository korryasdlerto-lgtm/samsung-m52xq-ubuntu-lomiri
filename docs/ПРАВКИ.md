## Журнал образа (прочитан из TWRP, образ смонтирован ro; journal-boot1/)

(2) **Настройки кодировщика по умолчанию убивают прошивку на ≥1080p** (профиль High, уровень 1): рабочие — `h264_profile=0` (Baseline), `h264_level=15` (5.1), режим фиксированного QP (`frame_level_rate_control_enable=0`, `h264_i_frame_qp_value`, `h264_p_frame_qp_value`, `h264_minimum_qp_value`; имена с суффиксом _value, без суффикса GStreamer молча игнорирует; RC Venus битрейт не держит). Результаты (чистая загрузка): videotestsrc 4K 33,7 к/с, 1080p 94,7 к/с, 720p 116 к/с; камера 4K → videoconvert NV12 (CPU) → Venus 28,2 к/с без ошибок прошивки (лимит — videoconvert); QP 34/36 ≈ 37 Мбит/с в 4K, QP 28/30 ≈ 175, QP 40/42 ≈ 6 (тёмная шумная сцена). РЕШЕНИЕ В КАМЕРЕ: в плагин m52xqcamsrc (build-m52xqcamsrc/gstm52xqcamsrc.c) добавлен элемент **m52xqvenc** (GstBin: videoconvert → NV12 → v4l2h264enc с этими настройками; QP по умолчанию 33/35, переопределяется M52XQ_VENC_QP="I,P"; ранг PRIMARY+100, класс Codec/Encoder/Video/Hardware, не регистрируется при M52XQ_NO_VENC или без /dev/video18) — encodebin камеры выбирает его сам; `v4l2h264enc` в ярлыке остаётся запрещённым (rank NONE). Тест: `gst-launch-1.0 -e libcamerasrc … ! video/x-raw,format=BGRx,width=3840,height=2160,framerate=30/1 ! m52xqvenc ! h264parse ! matroskamux ! filesink` → 63 МБ/12 с (≈42 Мбит/с), файл декодируется (baseline).
